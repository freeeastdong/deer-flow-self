# 2026-05-05 音乐电台 Agent 问题记录

## 问题概述

用户输入"想听周杰伦的稻香"后，Agent 在多轮对话中虽然口头上说"马上为你播放"，但**实际没有触发音乐播放**。

---

## 完整复现流程

### 第一回合

**用户**：我想听周杰伦的稻香

**Agent**：
> 好的，已经找到两个版本，请问你想播放哪个版本？

（正确行为：找到录音室原版 + Live 版，询问用户选择）

---

### 第二回合

**用户**：原版

**Agent**：
> 找到了！本地曲库里有周杰伦《稻香》的两个版本：
> 
> 1. **《稻香》** - 来自专辑《魔杰座 Capricorn》的录音室原版，时长3分43秒
> 2. **《稻香 (Live)》** - 来自《2010超时代演唱会》的现场版，时长3分42秒
> 
> 你刚才说想听原版，那么《魔杰座》专辑里的这个版本就是你要的录音室原版。这首歌用温暖的旋律和质朴的歌词，带我们回到童年乡间的美好回忆。
> 
> **好的，马上为你播放周杰伦的《稻香》原版。**

**实际结果**：🚫 **音乐没有播放**。Agent 说了"马上播放"但没有任何音频输出。

---

## 问题分析

### 可能原因

1. **前端确认词检测逻辑不匹配**
   - 用户说"原版"，不包含任何确认词（如"播放"/"听"/"好"等）
   - 前端 `PLAY_CONFIRM_WORDS = ['需要', '播放', '好的', '好', '要', '行', '可以', 'ok', 'yes', '嗯', '听', '放', '播']`
   - "原版"不在确认词列表中 → 走 LLM 流程

2. **LLM 回复含播放话术但无实际播放指令**
   - LLM 在回复末尾说"好的，马上为你播放..."
   - 但 LLM 并没有返回一个明确的"播放指令"给前端
   - 前端目前只在以下情况播放音乐：
     - 用户输入匹配确认词 + 匹配到 currentRecommendations 中的歌曲 → 前端直接播放
     - LLM 返回的 `data.audio_url` 是 TTS 音频，不是音乐

3. **LLM 没有调用播放相关工具**
   - 当前工具列表中没有"播放音乐"工具
   - LLM 只能通过文本回复表达播放意图，但前端无法从纯文本中可靠地提取播放指令

4. **前端缺乏"LLM 说播放就播放"的解析逻辑**
   - 前端只依赖确认词检测来触发播放
   - 对于 LLM 回复中说"马上播放"的情况，前端没有解析和执行的机制

## 待解决问题（明天继续）

### 🔴 P0：LLM 说"马上播放"但音乐不播放

**现象**：Agent 回复中出现"好的，马上为你播放..."，但无实际播放动作。

**根因**：前端播放触发机制只有两条路径：
1. 用户输入含确认词 + 匹配 currentRecommendations → 前端直接播放
2. LLM 返回 TTS → 播放 TTS（不是音乐）

**缺少路径 3**：LLM 回复文本中表达播放意图时，前端如何识别并执行播放？

**可能的解决方案**：

#### 方案 A：前端解析 LLM 文本中的播放意图
- 在 LLM 回复文本中检测"马上为你播放"等关键词
- 如果检测到 + currentRecommendations 中有数据 → 自动播放
- **缺点**：不可靠，LLM 措辞可能变化

#### 方案 B：LLM 返回结构化播放指令
- 后端 `chat()` 返回中增加 `action: "play" | "ask" | "none"` 字段
- 或者增加 `play_song_id` / `play_song_index` 字段
- 前端收到 `action: "play"` 时直接播放对应歌曲
- **优点**：可靠、明确
- **实现方式**：
  - 修改 `_llm_chat` 的返回格式，让 LLM 通过 function calling 或特定格式返回播放指令
  - 或者在 LLM 回复后做一次意图解析，判断是否是播放意图

#### 方案 C：增加 `play_song` 工具给 LLM
- 给 LLM 一个 `play_song(song_id)` 工具
- 当用户确认播放时，LLM 调用该工具
- 后端返回给前端时带上 `play_song_id`
- 前端收到后执行播放
- **优点**：最符合 Function Calling 范式

#### 方案 D：简化前端逻辑（推荐作为临时方案）
- 如果 LLM 回复后 `currentRecommendations.length === 1` → 直接播放
- 如果 `currentRecommendations.length > 1` 但用户已经做了选择 → 需要某种方式让前端知道用户选的是哪首
- 可以在 LLM 回复中夹带一个不可见的播放标记（如 HTML comment 或特定 JSON）

---

## 建议明天优先尝试的方案

**方案 B + C 结合**：
1. 给 LLM 增加 `play_song` 工具（工具参数：song_id 或 recommendation_index）
2. 系统提示词中教 LLM：当用户确认播放某首歌时，调用 `play_song` 工具
3. 后端 `chat()` 返回中增加 `play_song` 字段
4. 前端收到 `play_song` 后直接调用 `playRecommendedSong()`

这样既符合 Function Calling 范式，又避免了前端纯文本解析的不可靠性。
