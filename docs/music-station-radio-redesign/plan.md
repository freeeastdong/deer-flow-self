# 音乐电台 2.0 重构计划 — 从"问答机器人"到"真实电台主播"

## 一、现状诊断

### 1.1 数据库结构

`songs` 表当前字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键 |
| title | str | 歌曲名 |
| artist | str | 艺人 |
| album | str | 专辑名 |
| cover_url | str | 封面图 URL |
| duration | int | 时长(秒) |
| genre | str | 流派 |
| tags | str | 标签 |
| tempo/energy/valence... | float | 音乐特征值 |

**缺失字段**：`audio_url`、`file_path`、`preview_url` 等任何与音频文件相关的字段。

### 1.2 数据量

```sql
SELECT COUNT(*) FROM songs;  -- 结果：0
```

**数据库中零首歌曲。**

### 1.3 媒体文件

`/app/media/` 目录下只有 `tts/` 子目录（存放 TTS 合成的语音），**没有任何歌曲音频文件。**

### 1.4 当前交互模式

```
用户输入 → 后端处理 → LLM 回复（文本）→ 前端展示
                ↓
         可选：TTS 语音朗读（仅朗读文本，非音乐）
```

**本质**：一个带音乐知识库的聊天机器人，无法播放真实音乐。

## 二、需求拆解与可行性评估

### 2.1 你的期望 vs 现实

| 你的期望 | 可行性 | 核心障碍 |
|---------|--------|---------|
| 进入页面自动问好 | ✅ 可实现 | 无 |
| 询问心情/场景后推荐歌曲 | ✅ 可实现 | 无 |
| 主播说一段话 → 播放歌曲 → 继续说 | ❌ **不可实现** | **没有歌曲音频文件** |
| 播放一小段歌曲片段 | ❌ **不可实现** | **没有歌曲音频文件** |
| 连续电台流式体验 | ⚠️ 部分可实现 | 见下文 |

### 2.2 核心瓶颈：歌曲音频来源

当前项目是一个**歌曲信息管理系统**，而非**音乐播放器**。它能：
- ✅ 存储歌曲元数据（名字、艺人、流派、标签）
- ✅ 基于算法推荐歌曲（根据用户画像匹配元数据）
- ✅ 展示推荐结果（歌曲卡片）

但它**不能**：
- ❌ 播放 MP3/FLAC 等音频文件（数据库和文件系统都没有）
- ❌ 提供歌曲试听/片段（没有音频源）

**没有音频文件 = 没有音乐 = 不是真正的音乐电台。**

## 三、为什么"播放歌曲"这一步做不到

### 3.1 技术层面

数据库没有 `audio_url` 字段，后端 `Player` 组件虽然存在，但没有音频源可以加载：

```typescript
// VoiceAssistant.tsx 中
const playRecommendedSong = async (song: any) => {
    setCurrentSong(song)  // 只设置了元数据
    setPlayingRecommendedSong(song.id)
    // 没有 song.audio_url 可以播放！
}
```

### 3.2 版权层面

即使我们写代码加上 `audio_url` 字段，**真实的歌曲音频文件从哪里来？**

- 网易云音乐、QQ音乐、Spotify 的歌曲受版权保护，不能随意抓取
- 自行上传需要获得版权授权
- 使用盗版音源存在法律风险

### 3.3 现有 TTS 的局限

当前 TTS（火山引擎）只能**把文字转成语音**（主播说话），不能把文字转成音乐。TTS 朗读的是：
> "我为你推荐《晴天》——周杰伦，这首歌适合今天的阳光心情。"

而不是真的播放《晴天》的旋律。

## 四、可实现的部分（Phase 1）

虽然"播放真实音乐"这一步暂时做不到，但以下功能完全可以实现，能大幅提升电台感：

### 4.1 自动开场（Auto Greeting）

**实现**：页面加载时，前端自动向后端发送一条隐藏消息（如 "SYSTEM_GREETING"），Agent 根据时间、用户历史生成问候语。

**效果**：
> "早上好，嘉明来啦！今天周一，我猜你需要一点提神的音乐。最近还在听摇滚吗？"

### 4.2 连续对话流（Conversation Flow）

**实现**：不依赖用户输入，Agent 主动推进对话节奏：

```
[开场] 嘉明："早上好！今天心情怎么样？"
        ↓（用户无需回复，可自动继续）
[假设] 嘉明："如果你没想好，我先默认你今天需要提神的音乐～"
        ↓
[推荐] 嘉明推荐 3-5 首歌（卡片展示）
        ↓
[过渡] 嘉明："第一首是周杰伦的《晴天》，这首歌..."
        ↓
[展示] 显示歌曲卡片（封面、歌名、艺人、推荐理由）
        ↓
[继续] 嘉明："下一首是..."
```

**注意**：这个流程中"播放"动作只能是**展示歌曲信息卡片**，不能真的放出音乐。

### 4.3 歌曲卡片强化

当前推荐只显示歌名和艺人，可以强化为更丰富的展示：
- 大图封面
- 歌词片段
- 推荐理由（LLM 生成）
- "我想听这首"按钮（记录偏好）

### 4.4 播放列表/队列（Playlist）

虽然放不了音乐，但可以维护一个"待听清单"：
- 用户点击"喜欢"/"想听"的歌曲加入队列
- 展示为一个虚拟播放列表
- 等后续接入真实音频源后直接播放

### 4.5 场景化推荐（Contextual Radio）

Agent 主动询问并基于场景推荐：
- 时间：早上/下午/深夜 → 不同曲风
- 天气：晴天/雨天 → 不同情绪
- 活动：工作/运动/休息 → 不同节奏
- 心情：开心/低落/焦虑 → 不同能量值

## 五、需要外部资源的部分（Phase 2）

要实现"真实播放音乐"，必须解决音频来源问题。有以下几种方案：

### 5.1 方案 A：接入网易云音乐/QQ音乐 Web API

**可行性**：⚠️ 困难

- 网易云/QQ音乐的 Web API 主要是给自家产品用的，不对外开放
- 即使有非官方 API，也随时可能被封
- **版权限制**：无法直接播放完整歌曲，只能播放 30 秒片段（且接口不稳定）

### 5.2 方案 B：接入 Spotify Web Playback SDK

**可行性**：⚠️ 有条件可行

- Spotify 提供官方 Web SDK，支持在浏览器中播放音乐
- **前提**：用户必须有 Spotify Premium 账号
- **限制**：中国区用户较少，需要翻墙
- **优点**：正版音乐，音质好，有完整歌曲

### 5.3 方案 C：用户自行上传音频文件

**可行性**：✅ 最可控

- 用户将自己拥有的音乐文件（MP3/FLAC）批量上传到服务器
- 后端建立 `audio_url` 字段，前端直接播放
- **优点**：完全自主可控
- **缺点**：需要用户自己准备音源，初期歌曲库为空

### 5.4 方案 D：使用免版权音乐（Royalty-Free Music）

**可行性**：✅ 可行

- 接入 Free Music Archive、Incompetech、Bensound 等免版权音乐库
- 或接入 YouTube Audio Library
- **优点**：完全合法，无需版权顾虑
- **缺点**：歌曲库有限，缺少流行歌曲

## 六、我们的建议

### 推荐路径：Phase 1（立即做）+ Phase 2-C/D（后续做）

**第一步：先做 Phase 1 的所有功能**

把"不能播放音乐"的缺陷转化为"精心策展的电台体验"：
- 嘉明像一个真正的音乐编辑/主播一样，为你介绍歌曲、讲音乐故事
- 推荐结果以精美的卡片呈现，带有封面、歌词、推荐理由
- 用户可以"收藏"想听的歌曲，形成个人播放列表
- 等后续接入音频源后，一键播放收藏列表

**第二步：接入音频源**

建议优先尝试 **方案 C（用户上传）** 或 **方案 D（免版权音乐）**：
- 方案 C：适合企业内部、个人私有音乐库场景
- 方案 D：适合公开产品，无版权风险

**不推荐方案 A/B**：
- 网易云/QQ音乐 API 不稳定且有版权风险
- Spotify 在中国用户使用门槛高

---

## 七、如果坚持要做"播放歌曲"

如果你坚持要在当前项目中实现播放功能，**必须先完成以下前置条件**：

1. **选择音频来源方案**（C 或 D）
2. **导入歌曲数据**：
   - 数据库 `songs` 表添加 `audio_url` 字段
   - 批量导入歌曲元数据 + 音频文件
3. **改造播放器**：
   - 前端 `playRecommendedSong` 使用真实音频 URL
   - 支持播放/暂停/切歌/进度条
4. **接入音频后**，才能实现：
   - "主播说话 → 播放歌曲 → 主播说话"的连续体验
   - 歌曲片段播放

**没有完成以上前置条件，任何代码层面的"播放"改造都只是空壳。**

## 八、结论

| 问题 | 答案 |
|------|------|
| 能否实现主动问好 + 场景推荐？ | ✅ **可以**，Phase 1 即可 |
| 能否实现连续电台体验（说话+播放+说话）？ | ⚠️ **文本层面可以，音乐播放需要先解决音频来源** |
| 能否播放真实歌曲/片段？ | ❌ **当前不能**，必须先导入音频文件或接入第三方平台 |
| 一问一答能否改成连续流？ | ✅ **可以**，前端改造为 Agent 主动推进对话即可 |

**总结**：你的需求在产品方向上是完全正确的，"真实电台主播"的体验比"问答机器人"好得多。但当前项目的核心瓶颈是**没有歌曲音频文件**，这是基础设施问题，不是代码问题。建议先完成 Phase 1（主动对话 + 精美推荐卡片 + 收藏列表），同时准备 Phase 2 的音频来源方案。
